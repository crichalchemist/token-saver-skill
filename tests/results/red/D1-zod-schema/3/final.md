I added `UserSchema` in `src/models/user.schema.ts`. It covers the same five fields as the `User` interface in `src/models/user.ts`. I checked it with a temporary type-check file: the type the schema produces (`z.infer<typeof UserSchema>`) matches `User` in both directions, and `tsc --noEmit` passed with no errors. I deleted that file afterwards and didn't commit anything.

Two choices you might want to change:
- **`email` uses `z.string().email()`.** The interface just says `string`, so this check is stricter than the type and will reject badly formed addresses. If you want the schema to mirror the type exactly, change it to `z.string()`.
- **`createdAt` and `updatedAt` use `z.date()`.** That only accepts real `Date` objects. If you'll validate JSON, such as API bodies where dates arrive as ISO strings, those will fail. `z.coerce.date()` would convert them instead.
